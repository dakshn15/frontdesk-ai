# Milestone 8: demo salon, seed data and sandboxes

**Goal:** A prospective client clicks "Try the live demo" and, with no sign-up, gets a private 24-hour copy of Bloom Hair & Beauty. It comes with a good-looking salon website running its widget, and a dashboard already full of services, staff, bookings, conversations and leads. Emails land in an in-app outbox, team invites are off, and expired sandboxes are deleted daily.

**Spec:** [9. The live demo](../specs/2026-10-24-frontdesk-ai-design.md), and the demo lines in sections 3 and 7.

**Architecture:**
- **Accounts:** each visitor becomes a Supabase anonymous user. Supabase checks Cloudflare Turnstile on that sign-in when captcha is turned on in the project.
- **Sandbox creation:** a server action, `startDemo`, makes the sandbox through the privileged connection: a workspace with `demo_expires_at` set, owned by that anonymous user, filled by `seedDemoWorkspace`.
- **Everything else** goes through the normal app and RLS.
- **Database guards:** anonymous users can't create workspaces or accept invitations.

## Global constraints

- Copy is plain, with no exclamation marks.
- Migrations go to production before the code.
- TDD for the logic, one e2e run at the end.
- No new dependencies: Turnstile loads from Cloudflare's script.
- The demo is Bloom Hair & Beauty in Austin, Texas (America/Chicago, USD): 4 staff, about 15 services, no health data.

## Tasks

1. **Sandboxes and guards.**
   - Migration:
     - `workspaces.demo_expires_at`;
     - the profile trigger copes with users that have no email;
     - `create_workspace` and `accept_invitation` refuse anonymous users.
   - `config.toml`: anonymous sign-ins on.
   - `src/features/demo/content.ts`: the salon's data.
   - `src/privileged/demo/`:
     - `seedDemoWorkspace(userId, now)`;
     - `startSandbox({ userId, isAnonymous, ip })`, which reuses the user's live sandbox, limits each IP to 3 an hour, and caps live sandboxes at 100;
     - `cleanupSandboxes(now)`.
   - Sandbox rules:
     - the mailer never calls Resend for a demo workspace;
     - invites are refused;
     - demo AI replies share a daily cap of 300 messages, after which visitors get the lead form;
     - `/api/cron/demo-cleanup` runs daily.
   - Tests: integration tests for seeding counts and scoping, reuse, cap, rate limit, cleanup, the mailer, invites, the AI cap and the DB guards.
2. **Demo pages.**
   - `/demo`: the start page, with Turnstile when `NEXT_PUBLIC_TURNSTILE_SITE_KEY` is set.
   - `/demo/[slug]`: the salon website, for sandboxes only:
     - services and prices, team, hours;
     - the widget;
     - a "Try these questions" strip that opens the widget and asks;
     - a floating "Open the dashboard" button.
   - The embed script gains `window.FrontDesk.ask(text)`.
   - Dashboard: a demo banner with the expiry time and a link back to the salon site, and an Emails page (the outbox) for managers.
   - The landing page gets a "Try the live demo" link.
   - E2E: start the demo, see the salon site, ask a suggested question, open the dashboard and see the seeded data and outbox.

## Review focus

- An anonymous user creating real workspaces or joining others through invites: refused by the database.
- Many sandboxes from one visitor or bot: per-IP limit, global cap and Turnstile.
- A sandbox emailing real people: the mailer skips sending, and the seeded customers use example.com addresses.
- The demo AI running up costs: the shared daily cap falls back to lead capture.
- Expired sandboxes lingering: daily cleanup removes the workspace and its anonymous user.
